# cc26: way-back grey streets on the unit (18 Nov 2026)

Status: on the unit since 18 Nov (stationary check passed; ride: one crash, line mostly `wb10`, no grey; R-RIDE fix on the host). The device test pack (`.local/cc26-pack/`) is complete on the
host: the image, R1 (way-back version 2, no layer), R2 (scheme D), R3 (version 2 with the grey layer), the pack manifest
and the storage step. It is run in one session with the owner's approval for each step.

## What changed

- **Candidate fixes (D0):** the candidate builders require `--base` (cc23wb); each overwritten range is checked for
  incoming references (guidance and loop-start); trampoline frames are pinned; callees are checked in full; the line
  over 32 points shows `wb10`; the cc23 code page keeps its 1,768 B reserve; the version text carries the build mark.
- **Route identity (owner ruling):** before a file is sent, the page drops the way-back data when its identity does
  not match the route bytes in front of it.
- **Way-back version 2 (D1b, D2):** 8 B nodes with the grey flag (bit 63) and the ride distance (bits 51 to 62). Forward
  mode is removed. Version 1 is refused by the unit.
- **Grey layer (D3a, D3c):** a section after the extras (`CCGL`, E15). The page joins the grey streets into cell
  polylines. The unit reads the cells under the heading-up screen (D3c-H, below).
- **Adapter (D5):** off the route, the grey streets are drawn before the line (operation 30, at most 400 segments,
  60 ms). The line and the text are as on cc23. `wb3` on the route is removed.
- **Second code area (D4, E8):** 20,172 B after the DROM constants, executed at 0x4237b134.

## Correction D3c-H: the map is heading-up

The first cc26 build used a north-up box. The map is heading-up (owner, 18 Nov): the top of the screen is ahead.
The image of 1099aa2 must not go on the unit.

- `wb_grey_cells` takes the course (0..359, clockwise from north). It returns the cells under the turned screen
  (600 m wide, 520 m ahead, 100 m behind; separating axes, integer sine), nearest first, at most 20, in at most 5 rows.
- The adapter reads the stock map heading `*(float *)0x3c388d08` (450 − course) in each frame and keeps no state.
  A NaN or a value outside −360..720 draws no grey; the line and the text do not change. A new navigation with no
  movement has heading 90 (course 0): the map and the grey are north-up in that state.
- The grey simplify tolerance is 2.5 m (one pixel, was 1.25 m): 70 km layer 230,489 B (was 242,616 B). The numbers
  table above is from the north-up box and the 1.25 m tolerance.
- Device compiler: code 6,996 B; stack `wb_grey_lines` 976 B, `wbd_run` 352 B (sum about 1,872 B, limit 3,360 B in the bcc6792 image).

Stack of the adapter path (device compiler, `-fstack-usage`): `wbd_frame` 480 B, `wbd_run` 352 B, `wb_grey_lines`
976 B, `wbd_grey_visit` 32 B, `wbd_read` 32 B. Sum about 1,872 B, limit 3,360 B.

## Correction R-STACK (review, 18 Nov): `WBD_STACK` 3,968 B

The review gate (`tools/review_gate.py`, G4) adds the frames of the deepest path from `wb_rt` in the device compiler
call graph: 2,064 B (upper bound, through `wb_grey_lines`). With a limit of 3,360 B, the stock calls (`fread`,
`cc_line`) kept at least 1,296 B. On the ride-tested cc23 they kept at least 1,904 B. Their real use is not measured.

- `WBD_STACK` is now 3,968 B (`firmware/wayback/wb_device.c:14`), so the stock calls keep at least 1,904 B again.
- With less free stack, the unit shows `wb8` and draws no line (no file call). The device test reports each `wb8`.
- Code bytes do not change (6,996 B). The image of bcc6792 must not go on the unit.

## Known gaps

- `tramp_rt` (0x420496b0) is a live way-back hook inside the stock span that the D0 item 2 rule calls dead. No
  candidate overwrites it. Its literal (the hook word) changes on cc26.
- The unit checks the way-back identity against its own header, not against the route bytes. The page does that check.
- The 3 km way-back reach does not fit version 2 (distance field of 12 bits).
- The free stack of the task at the hook is not measured. If it is below 3,968 B, every frame shows `wb8`.
- One crash on R3 (18 Nov ride). The cause is not known (see Ride result).

- **Crash, one time, about 40 s after R3 started (first GPS fix).** Task `AppGUIManage`. Stack: map frame → `cc_gate` →
  trampoline 0x42049670 → `cc_iter` → `draw_entry` → projection 0x4204c1bc → `cc_line` → `line` (v21 map draw) →
  stock canvas line → stock fill loop at 0x42025172 (`addi.n`, an instruction that cannot fault). EXCCAUSE in the
