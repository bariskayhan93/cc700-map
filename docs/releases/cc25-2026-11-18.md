# cc25 release record, 2026-11-18

cc25 stores map blocks in scheme D. The patched firmware reads them through one hook word and one module.
This record does not flash a device. The owner approves each device step in chat.

## What changed

- The page has a new firmware choice, **Patch cc25+**. It writes scheme D blocks by the route option `codec: 'd'`.
  The other choices write today's files.
- `js/map_codec.js` encodes and decodes scheme D version 1 (E1 to E3 of the plan).
- `firmware/mapdec` is the device module `cc_entries` (E4). It replaces the entries callback literal at `0x4203e3ec`.
  The code is at `0x421de800`. Old blocks go to the stock callback.
- `tools/cc25_build.py` builds the image from the exact cc23 base with the trampoline fix. It changes only the code,
  the literal and the version text.

## Device test (not run)

- **Hypothesis.** cc25 draws a scheme D route as cc23 draws the same route in today's format. Old routes draw as before.
- **Old-firmware check (before the flash, on the installed image).** Open route 2 for 1 minute.
  Expected: the map area is empty and the unit does not restart. This would show that the E1 record reads as one
  empty entry on the stock decoder.
- **Observation.** Route 1 is a GPX made with `patch`. Route 2 is the same GPX made with `patch25`. Open each route for
  2 minutes, stationary, at the same place. Take photos. Then ride 10 minutes on route 2 through two block changes.
  Expected: no restart, and `/ABNORMAL/` is empty.
- **Duration.** 35 minutes.
- **Restore.** Install `.local/mining/ota_1_cc23trampfix.bin` (`d225e179…`). Delete route 2.

## Gaps

- Not run on a unit. Frame time and heap use are not measured.
- The stock point callback and the stock free loop are not changed.
- The drawing of the E1 empty entry on old firmware is not tested on a unit. Only the old-firmware check tests it.
- The stock allocator addresses and the caps `0x404` come from the disassembly of the base image. The module is not
  tested on a unit.
- The host stock model approximates the stock callback for protobuf entries. It is used only in the fallback and
  sequence tests.
- A block with a count and no entry record leaves the stock iterator with no array. The host harness clears the count.
  The device has no such guard. The page does not write such a block.
