# Preview parity and cycling semantics

User authorized implementation and publication without another design pause.
Keep existing green/grey fills. Default preview represents installed v18, not a
new firmware palette. A separate cycling study distinguishes water/cycleways
and makes the route opaque without pretending the installed patch changed.

1. Preview: native map dimensions, RGB565 colors, integer geometry, port patch
   scanline/dash operations, use encoded arrows and firmware label clipping.
   Browser line rasterizer/font/projection remain explicit approximations.
2. Generator: retain unknown track surfaces; rough markings require positive
   tag evidence. Read original observations from cached cells when available.
3. UI: select installed appearance or clearly labelled preview-only study;
   retain decoded route as the source and cache every new offline dependency.
4. Verify public tests/offline probes, historical/private loop, review the final
   diff, publish Pages, compare served files with the published commit.

Cycling hierarchy references: https://www.cyclosm.org/legend.html and
https://osmand.net/docs/user/map-legend/osmand/ . No new device firmware is
installed by a web deployment. Pixel-exact LVGL/font and runtime GPS parity
require further evidence, not a claim based on host tests.
